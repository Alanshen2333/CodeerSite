## 严重与高风险待办

- [ ] **生产默认密钥保护未生效**：`ProductionConfig.init_app()` 未被应用工厂调用，应用可带公开默认 `SECRET_KEY` / `JWT_SECRET_KEY` 启动。修复后轮换任何可能使用过的密钥。
- [ ] **生产链路使用 HTTP**：Nginx、Gitea 公网地址和 OAuth 回调未强制 HTTPS；补 TLS、HTTP→HTTPS 跳转、HSTS，并检查代理可信边界。
- [ ] **Gitea 凭据暴露面过大**：`/api/auth/git-credentials` 返回嵌有长期 token 的 URL，PAT 使用 `all` scope。改用 SSH 或短期最小权限凭据，禁止 token 进入 URL、日志和浏览器持久存储。
- [ ] **看板跨项目对象级越权**：卡片更新/删除/移动未验证卡片和目标列属于 URL 中项目。使用 `project_id + card_id/column_id` 约束查询并补跨项目攻击测试。
- [ ] **停用账号的旧会话仍有效**：JWT 用户加载与 refresh 未检查 `is_active`。停用用户、修改密码时应吊销所有会话，建议引入 session/token version。

## 中风险与纵深防御

- [ ] 邮箱验证码改用 `secrets`，数据库仅保存摘要，并增加用户/IP 失败次数限制和锁定窗口。
- [ ] 密码最低长度从 6 位提高，并增加常见泄露密码检查。

- [ ] Docker 基础镜像和 GitHub Actions 固定到不可变 digest/commit SHA。
